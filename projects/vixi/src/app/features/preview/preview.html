How should I structure the Sivaxi platform as it grows into multiple products?
Vixi

I'd approach Sivaxi as a product ecosystem, with clear boundaries between shared platform capabilities and individual products.

1. Start with the shell

Use the Angular shell for global navigation, authentication, theme, and shared UI. Keep product-specific features inside their respective remotes.

Suggested structure
sivaxi-shell/
├── shared/auth/
├── shared/theme/
├── projects/vixi/
└── projects/portfolio/

2. Keep responsibilities separate

  • Shell: navigation and global application layout.
  • Shared libraries: authentication, theme tokens, reusable UI.
  • Product remotes: product-specific screens and workflows.
  • Backend services: APIs and domain logic.

That gives you room to evolve products independently without duplicating every common capability. Start with these boundaries and introduce more complexity only when the product needs it.
